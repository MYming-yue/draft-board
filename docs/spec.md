# Draft Board 公开规格

应用版本：0.2.0。无集合的新文件 `formatVersion` 为 1.0，首次集合操作后升级为 2.0（不自动降级）；批次 `batchVersion` 仍为 1.0，应用版本不等同于文件格式版本。

本文随源码维护，描述当前 `.draft` 格式、Agent 批次和编辑行为。类型的精确载荷定义见 [`src/model/types.ts`](../src/model/types.ts)，运行时校验见 [`validate.ts`](../src/model/validate.ts)。当前没有单独发布可供通用 JSON Schema 校验器加载的 schema 文件；不能把 TypeScript 类型检查当作运行时输入校验。

## 1. 范围与实现边界

核心对象是带身份的卡片与关系。保存、复制、撤销、回放与 Agent 修改应保留可编辑结构。界面与 CLI 共用操作词汇；一次 Agent 批次对应一个历史步骤。

模型校验、ZIP 读取和浏览器界面的能力并不完全等价。例如 `parseBoard` 验证载荷形状与资源引用，不能视为对任意外部历史的完整回放验证。处理不可信文件的完整资源配额与恶意 ZIP 防护仍需加强。

## 2. 数据契约

### 2-A. 容器

`.draft` 是 ZIP，包含 UTF-8 `board.json` 和零到多个 `assets/<assetId>.png|jpg|jpeg` 图片。图片随文件携带，禁止外部绝对路径引用；单个资源声明大小为 1–5,242,880 字节。缺失资源应明确报错。

### 2-B. board.json

| 字段 | 内容 |
| --- | --- |
| `formatVersion` | 支持 `"1.0"` / `"2.0"`；其他主版本拒绝读取 |
| `board` | `id`、`name`、`createdAt`、`updatedAt`、`contentVersion`、`view` |
| `nodes` | 卡片数组 |
| `collections` | 可选集合数组，旧文件缺省为空；详见 §7 |
| `edges` | 关系数组 |
| `assets` | 图片元数据数组：`id`、`mime`、`path`、`bytes` |
| `history` | 历史步骤数组；脱历史分享时为空 |

`view` 含 `panX/panY/zoom`，zoom 范围为 `(0,10]`。节点、边、资源、白板的 ID 分别使用 `n_`、`e_`、`a_`、`b_` 前缀，后接 6–32 个字母、数字、下划线或短横线。

节点公共字段：`id/type/x/y/w`，可选 `h/accent/captionExpanded/coreScale/captionW`。位置是有限世界坐标，宽度大于零，`h` 可缺省、为 null 或为正数。颜色为 `default/blue/green/amber/red`。`captionExpanded` 为布尔值，缺省或 `false` 表示未选中时备注按 15 行截断；`true` 表示阅读态常驻展开。`coreScale` 为普通文本核心比例，缺省 1。`captionW` 为备注阅读宽度。

- `type=text`：必须含 `markdown` 字符串，可含独立 `caption` 字符串。
- `type=image`：必须含 `assetId`，可选 `markdown` 作为图片说明；不使用 `caption`。
- 普通文本卡以 `markdown` 为核心表达，居中、18px×`coreScale` 强调呈现；解释由独立 `caption` 承载，默认可见、左对齐、13px 较弱颜色。核心区阅读态只按编辑源码中的换行分行，不按宽度自动折行；编辑态同样不自动折行，用 Enter 控制阅读分行。不根据字数自动把正文迁移到备注。
- 文本/公式卡外框宽度为 `max(核心区宽, 备注阅读宽)`。四角手柄在**卡片外框**四角（与原公式卡相同），比例由指针相对按下点的距离决定（往外放大、往里缩小），等比缩放核心，备注字号不变。左右手柄只改 `captionW`（最低 `max(220, 核心宽)`，最高 800），不能压缩或拉长核心文字。缺省 `captionW` 时有备注则至少 220。
- 纯公式文本卡的 `w/h` 仍描述公式区域，公式居中并等比缩放；备注以正常字号排列在其下方。图片保持原比例，外框高度包含可见说明。关联圆点在所有卡片右边框外 24px。
- 备注阅读态默认最多 15 行，超出截断；单击选中卡片时展开全文。编辑区固定 15 行高，并提供「常驻展开」开关（默认关闭），写入 `captionExpanded`。结构视图仍整段隐藏备注。
- 纯公式由 Markdown 去除首尾空白后是否整体为单个 `$...$` 或 `$$...$$` 判断；混合正文保留普通卡片布局。渲染失败保留源码。

边包含 `id/kind/from/to/directed`，可选 `label`。`parentChild` 必须有向、单父、无环；`association` 可以跨分支与形成循环。

兼容性：新读取器接受无 `caption` / `captionExpanded` / `coreScale` / `captionW` 的旧文件。增加 `updateNodeCaption`、`setCaptionExpanded`、`setCaptionWidth` 以及 `resizeNode.coreScale` 后，包含这些操作的历史可能被旧程序以 `E_SCHEMA` 拒绝；不能仅凭 `formatVersion=1.0` 推断双向兼容。

### 2-C. 操作词汇

所有操作由模型统一执行，`before` 根据真实当前状态重新生成。调用方通常传入 `before: null`；完整历史保存归一化后的 `before/after`。

| op | 标识 / 载荷 | after |
| --- | --- | --- |
| `addNode` | `node` | 完整 node |
| `removeNode` | `nodeId` | null；before 保存节点及其边 |
| `updateNodeText` | `nodeId` | `{markdown}`，含图片说明 |
| `updateNodeCaption` | `nodeId` | `{caption: string或null}`，仅 text；null 删除字段 |
| `moveNode` | `nodeId` | `{x,y}` |
| `resizeNode` | `nodeId` | `{w,h, coreScale?}`；`coreScale` 缺省不改，`null` 删除字段 |
| `setNodeAccent` | `nodeId` | `{accent}` |
| `setCaptionExpanded` | `nodeId` | `{expanded: boolean}`；`false` 删除字段 |
| `setCaptionWidth` | `nodeId` | `{captionW: number或null}`；null 删除字段 |
| `addEdge` | `edge` | 完整 edge |
| `removeEdge` | `edgeId` | null |
| `updateEdge` | `edgeId` | `{from,to,label?,directed}` |
| `reparent` | `nodeId` | `{parentId: string或null}` |

### 2-D. Agent 批次

```json
{
  "batchVersion": "1.0",
  "boardId": "b_example0",
  "baseContentVersion": 0,
  "actor": "agent",
  "label": "添加一个想法",
  "ops": [{
    "op": "addNode",
    "node": {"id":"n_example0","type":"text","markdown":"一个想法","x":80,"y":80,"w":240},
    "before": null,
    "after": {"id":"n_example0","type":"text","markdown":"一个想法","x":80,"y":80,"w":240}
  }]
}
```

替换为实际 `boardId` 和当前 `contentVersion` 才可提交。校验顺序为批次形状 → 白板身份 → 版本 → 各操作。任何一步失败，整批不提交。CLI 的 `validate` 仅验证，`apply` 验证后使用同目录临时文件与重命名写回；这不是跨进程文件锁，同时运行的外部写入者仍需自行协调。

### 2-E. 结果与错误

成功：`{"ok":true,"contentVersion":1,"appliedOps":1}`。

失败：`{"ok":false,"error":{"code":"E_VERSION_CONFLICT","message":"..."}}`，CLI 退出码 1。操作相关错误可含从零起的 `opIndex` 和 `path`；未应用操作数不作为失败结果字段返回。

封闭错误码：`E_SCHEMA`、`E_BOARD_MISMATCH`、`E_VERSION_CONFLICT`、`E_DUP_ID`、`E_UNKNOWN_NODE`、`E_UNKNOWN_EDGE`、`E_UNKNOWN_ASSET`、`E_PARENT_CYCLE`、`E_MULTI_PARENT`、`E_ASSET_MISSING`、`E_FORMAT_UNSUPPORTED`。

## 3. 行为契约

### 3-A. 分支

双击画布空白处创建文本卡时，新卡以双击点为锚点直接落下并进入编辑；即使新卡外框与附近卡片重叠，也不自动跳到其他位置。用户可在编辑完成后自行拖动。Tab 建子卡、Shift+Enter 建同级卡及粘贴文本卡的既有避让规则不变。

Tab 创建子卡；Shift+Enter 创建同级卡。存在树父时同级卡与源卡同父；没有树父时继承源卡的入向关联（标签留空）。`reparent` 保留普通关联线，拒绝父子环。删除单卡保留其子卡但移除相关边；删除整条分支是独立动作。

### 3-B. 复制

复制组内节点和边时生成新 ID，并映射新端点；组外边不复制。整次粘贴是一个可撤销步骤。

### 3-C. 批次与版本

```gherkin
Scenario: 批次成功
  Given 白板 contentVersion 为 7
  When 提交基于版本 7 的合法批次
  Then contentVersion 为 8，history 增加一个 actor=agent 的步骤

Scenario: 中途失败
  Given 批次的第一个操作合法，第二个引用不存在的节点
  When 执行 apply
  Then 返回 E_UNKNOWN_NODE，opIndex 为 1
  And 文件字节、内容版本、历史全部保持原样

Scenario: 版本冲突
  Given 文件版本已经变为 8
  When 再次提交基于版本 7 的批次
  Then 返回 E_VERSION_CONFLICT，文件不变
```

### 3-D. 历史与回放

步骤包含 `seq/at/actor/label/base/result/ops`。`seq` 从 1 连续递增，`result=base+1`。撤销追加逆操作，重做追加正向操作；拖动过程中不逐帧写历史。公式正文与备注同时提交时属于一个步骤。

完整历史的回放从空卡片 / 边 / 集合数组开始，使用当前资源表重建内容；不回放资源二进制的演化。“只分享当前草稿”保留当前内容和 contentVersion，移除历史。当前回放器没有独立快照基线，因此脱历史文件再编辑后形成的部分历史不能保证完整回放，这是已知边界。

## 4. 不变式与交互几何

Ctrl+左键点击卡片将该卡加入当前选区，可连续选择多张卡片，重复点击不重复添加；按住 Ctrl 双击不触发建卡或编辑。按住 Ctrl 从画布空白处左键拖动显示矩形捕网；松开后把矩形接触到的卡片加入当前选区，边界相切也算命中；空白处单击不清除已有选择。捕网按实际可见卡片外框与当前缩放换算，选择操作不写入文件或历史。普通右键不改变选区；原有 Shift+左键框选继续可用。

I1：边端点存在，删除节点同步删除关联边。I2：父子图单父无环。I3：各类 ID 唯一，复制不共享身份。I4：布局整理只移动节点，不改变内容或关系。I5：内容版本按步递增，历史追加。I6：完整历史的回放内容应与保存内容一致。I7：图片引用对应内嵌资源。I8：CLI 通过临时文件重命名提交写盘。I9：未知文件主版本明确报错。

拖动吸附先按卡片实际外框筛选附近候选，再寻找边缘 / 中轴线。目标 B 的搜索半径为 `clamp(0.5 × B的屏幕对角线, 96, 320)` 屏幕 px；A 与 B 外框的最短距离进入此范围时 B 才是候选。对齐容差另为 8 屏幕 px，X/Y 独立选择最近对齐线，多选使用整体外框。Alt 换父拖动不触发普通对齐。

布局整理依据 `parentChild` 向右排树，使用点击时 DOM 的实际可见外框（含当前显示的备注），读取 border-box 的 CSS 使用尺寸（世界坐标，不受画布缩放的浮点误差影响），尺寸向上取整。字体、图片或卡片未完成加载时不执行，提示加载后重试；卡片编辑态与回放态禁用。顶栏“布局整理”始终整理全板，即使有选中卡片；按住 Shift 点击时只整理选中卡片及其父子后代。同时选中祖先和后代时只保留祖先根，重复 ID 去重。完成后在顶栏显示移动卡片数；若再次整理无需移动，显示“已按当前规则排好，无需再移动”；若求解器无法得到更好的无冲突布局但现有布局无冲突，显示“未找到更好的无冲突布局”，避免把求解失败误报为已排好。

兄弟分支按整理前 Y、X、ID 排序，保留原有上下顺序。父子水平间隔 36、兄弟子树垂直间隔 16 世界单位，父节点垂直居中。单个分支尽量保留根位置。多个独立分支按原分支整体外框的顶边、左边、ID 排序，以参与整理内容的原左上角为锚点，从左到右分行排列，分支间距 24。属于同一集合且整条分支均为该集合成员的分支先排成连续区块，区块外框包含集合实际边界及至少 12 世界单位的留白，再与其他分支一起分行；共享成员在本次布局中归入第一个可容纳其完整分支的集合区块，不改变文件中的多重成员关系。行宽候选由不同列数的连续分支最大宽度和 `sqrt(Σ((分支宽+24)×(分支高+24))×当前画布宽高比)` 构成，选择最终轮廓宽高比接近画布、占地较小且各行宽度均衡的候选，避免末行孤卡。行内顶对齐，行高取本行最高分支；优先得到接近窗口比例的规整矩形，不保证数学上的最小面积。布局完成后自动执行一次适应视图，留约 4% 的窗口边距，最大缩放为 3 倍；普通“适应视图”按钮仍沿用 80 像素边距、最大 2 倍。适应视图把卡片、集合及可见关系线纳入边界。

避让以每张实际卡片外框为准，树内部空白不当作实心障碍。与未参与整理的卡片发生碰撞时，先整组向下平移直到留出至少 16 世界单位，不挪动未选中的卡片。随后检查可见卡片外框之间至少 10 世界单位的间隔、可见关系线与非端点卡片之间至少 10 世界单位的间隔，以及非成员卡片与集合边界之间至少 10 世界单位的间隔。矩形集合按整个边界框检查，圆形/椭圆形按实际椭圆范围检查；一张卡片属于多个集合时，对每个非成员关系分别检查。关系线按实际二次/三次贝塞尔路径采样并检查线段与外框的交点，不要求关系线彼此不交叉，也不要求关系线避开集合边界。对同样能减少冲突的候选位移，比较移动后的整体轮廓宽高比、占地面积和位移距离，优先保留接近当前窗口比例的紧凑解。避让仅移动本次选择的卡片及其父子后代，集合成员身份、边、内容均不改变。局部整理不处理未选中元素之间原有的碰撞；若当前参与元素的冲突仍无法解决，则不提交移动并提示用户调整。

全板整理在避让后保持原左上角锚点；UI 最多尝试 8 轮重新排版，保留最近一轮已验证无冲突的结果，后续轮次失败不得抹掉前一轮成功布局。当前画面本就无冲突而新求解失败时，保持原位置并执行适应视图；若当前整体宽高比相对窗口的对数偏差小于 0.3，视为已排好，否则提示未找到更好的无冲突布局。耗时求解期间按钮显示“整理中…”并阻止重复点击。重复点击且内容、显示状态与窗口比例不变时位置保持稳定；无变化不增加历史。后续展开备注、编辑文字、缩放卡片或切换结构视图导致外框变大时，可重新整理；本操作不锁住后续手动布局。无 DOM 的模型调用方可传入 `LayoutGeometry` 和目标宽高比；未传时仍以存档 w/h（缺省高度 120）估算，模型只执行基础树布局，UI 的关系线/集合避让及视图适配不在离线模型调用中执行。所有移动同一步提交，可一次撤销，文件格式和操作词汇不变。回归入口为 `src/model/layout.test.ts`、`src/ui/layoutConstraints.test.ts`、`src/ui/layoutPlanner.test.ts` 与 `npm run smoke:layout`，已纳入完整 `npm run check`。

## 5. 结构视图与编辑

单向或无向连线根据卡片实测外框与中心连线确定边框锚点，曲线在各锚点沿所在边的法线进出：上下边竖直，左右边水平。上下对齐的卡片呈直线，纵向错位时平滑过渡；控制臂长度取端点在法线轴上距离的一半，不使用欧氏距离或固定最小值，避免短间距、横向错位时额外回折。双向关联仍保持两侧分离曲线。该调整同时适用于父子边与普通关联，不改变文件数据；说明与点击区域跟随新路径。

画布拖动建立有向关联时，同一 `from→to` 只保留一条：重复连接用同一步的 removeEdge + addEdge 覆盖旧关联（包括旧说明），可撤销恢复；反向关联和父子边不受影响。A→B 与 B→A 同时存在时采用向相反侧弯曲的曲线，点击区域、说明及说明编辑框跟随各自路径。删除反向边后恢复单线布局。旧文件中的同向重复关联只显示最后一条，保留原始数据及历史；再次连接该方向时清理重复项。底层 addEdge 的旧文件/历史重放语义保持不变；CLI 若需要相同覆盖行为，应显式提交删除旧边并添加新边的同一批次。

默认显示备注。工具栏“结构视图”全局隐藏文字、公式、图片的备注，外框收拢，连线、框选与吸附跟随可见外框；“显示备注”恢复。切换不移动节点，不改 `BoardFile`、contentVersion 或历史，也不随画布缩放自动切换。它是当前会话的显示状态，不写入文件；`.draft` 保存始终包含备注，PNG 导出反映当前可见视图。进入编辑时仍显示完整字段，避免隐藏待修改内容。

所有文本卡编辑器提供核心表达与备注两个区域；同次提交为一个历史步骤，Esc 取消两者修改。图片仍以 markdown 存说明。插入工具条作用于当前聚焦的字段。备注编辑区为 15 行；「常驻展开」与正文/备注同次提交。

最近操作的卡片（包括选中、拖动、开始编辑或建立关联）位于其他普通卡片上方；取消选中或拖动结束后仍保持该层级，直到操作另一张卡片。卡片下方的“添加备注”／“编辑备注”入口随卡片一起置顶，重叠时仍可点击。任何卡片（文本、公式、图片）进入编辑态时，整张卡片及其编辑控件临时位于画布最上层，高于其他卡片、连线及其控件；提交或取消后回到最近操作卡片的层级。层级只影响当前会话的显示，不重排节点数组，不写入文件或增加历史步骤。

编辑工具条分别提供「公式积木」与「希腊字母」面板，互斥展开，插入当前聚焦的正文或备注选区并恢复输入焦点。公式积木插入可编辑 LaTeX 源码（在公式分隔符内使用），包括绝对值、平均值横线、范数、向量、帽子、时间导数、导数、极限、连乘、对数、分段函数、正体单位/化学式、反应条件箭头、可逆反应及常用运算/关系符；相似符号按钮显示 `∼`，插入 `\sim `。保留原有分式、根式、上下标、求和、积分、偏导、矩阵与括号。

希腊字母面板提供 24 个大小写字母、常用变体，以及 τ（tau）和 ∇（nabla，常用于梯度 ∇f）；插入 Unicode 符号以兼容正文与公式。排序按最近插入优先，重复使用移到首位，未使用项保持字母表顺序；使用记录在本浏览器跨卡片、跨白板、刷新后共享，以 localStorage 保存，存储不可用时退回会话记录。该偏好不写入 `.draft`，不增加白板历史；取消编辑不回退使用记录。

有序列表按钮插入同层下一项序号：依据光标前连续列表最近一项递增，跨空白段落或普通正文重新从 1 开始，不受光标后列表影响。保留当前列表缩进；本次不引入 `1.1` 式多级编号。上述编辑变化不增加字段或 op，无集合的 1.0 文件无需升级，batchVersion 仍为 1.0；集合的格式升级规则见 §7。旧程序呈现布局可能不同。

## 6. 浏览器保存与离开保护

白板名称存于 `board.name`，磁盘上的 `.draft` 文件名由文件句柄或下载名决定，两者可以不同。新建白板且尚未绑定已有文件时，修改白板名称会同步更新保存时的建议文件名；打开已有文件后修改白板名称，保存仍写回原文件，或在下载回退模式下沿用打开时的文件名。需要改变磁盘文件名时使用“另存为”。

白板有未落盘修改（`dirty`）、正在保存（`saving`）、保存失败（`error`），或卡片／连线说明仍处于编辑态时，刷新、关闭标签页及离开页面须触发浏览器原生确认。取消离开时，当前页面和内存内容保持不变；已保存且无正在编辑的卡片时不提示。浏览器决定提示文案，应用不能自定义。

取消保存文件选择不算保存成功，原有未保存状态保留。异步保存只可将其启动时对应的编辑版本标记为已保存；保存过程中发生的新修改仍是未保存状态，继续等待后续保存。新建或打开其他白板后，旧保存回调不得改变当前白板的文件句柄、文件名或保存状态；同一白板继续编辑时，首次保存成功仍绑定该文件句柄，新增修改保持未保存。此保护不代替将白板保存为 `.draft` 文件，也不保证浏览器崩溃或断电后恢复内存内容。

测试对应关系与提交门槛见 [AGENTS.md](../AGENTS.md)。修改本规格时必须核对实现；已知边界不能通过修改文字假装已解决。


## 7. 集合（2026-09-25）

集合表达多张卡片的内在关系，是独立实体，不是卡片或父子边。一个卡片可以属于多个集合；本期不支持集合嵌套。成员关系由显式 `nodeIds` 保存，几何包含或拖入拖出不会自动改变归属。

### 7-A. 数据与操作

`collections` 元素字段：`id`（`g_` 后接 6–32 个字母、数字、下划线或短横线）、非空 `name`、可选字符串 `description`（关系说明）、`shape`（`rectangle|ellipse|circle`）、无重复 `nodeIds`、有限数值 `x/y`。所有成员必须存在，集合 ID 唯一。`x/y` 保存空集合的落点；非空集合边界由成员可见外框推导，不存储 UI 测量值。

| op | 载荷 | before / after |
| --- | --- | --- |
| `addCollection` | `collection` 完整对象 | null / 完整对象 |
| `updateCollection` | `collectionId` | 原对象 / 完整新对象，ID 不变 |
| `removeCollection` | `collectionId` | 原对象 / null |

所有操作进入共享模型、原子批次、历史和版本检查。`before` 从真实状态重算。重复集合 ID 返回 `E_DUP_ID`，成员不存在返回 `E_UNKNOWN_NODE`，非法形状、重复成员、集合不存在或更新身份返回 `E_SCHEMA`。删除卡片自动从所有集合移除其 ID，`removeNode.before.collections` 可选保存受影响集合快照，撤销恢复全部归属。集合最后一张卡片被移除后保留为空集合。

任一集合操作后文件格式为 2.0，撤销不降级。保存带集合的外部对象时也写为 2.0。新版读取无集合的 1.0 文件；旧程序必须通过主版本检查拒绝 2.0，防止脱历史分享文件中的集合被静默丢弃。批次版本仍为 1.0，增加上述三种操作；旧 CLI 不支持这些操作。旧文件内既有卡片、边、资源 ID 不迁移。

### 7-B. 显示与操作

多选卡片后点击画布顶部工具栏“所选建集合”。新集合默认矩形，支持编辑名称和关系说明、切换矩形／椭圆／圆形。边界使用细实线与柔和阴影，标题带成员数；位于卡片和连线下方，内部不阻挡编辑、平移和框选。名称和说明在失焦或 Enter 时提交（输入法组字的 Enter 不提交）。集合菜单可访问重叠或空集合。

矩形按成员实际可见外框增加横向 40、纵向 50 世界单位留白。椭圆在此基础上宽高乘 √2，圆形以该矩形的对角线为直径，确保成员四角在边界内。备注显示、缩放和卡片移动均更新边界；这些派生测量不写历史。空集合显示 240×160，圆形为 240×240。

拖动标题或边界整体移动成员，松手提交一个步骤；取消指针操作不提交。共享成员只移动一次，其他集合边界随之变化，但其他非共享成员不动。选择集合后可以“选择成员”，再用现有卡片操作。按住 Ctrl 多选卡片后可“加入所选”或“移出所选”；不会改变这些卡片在其他集合中的归属。“解散集合”只删除集合，卡片、连线保持不变；集合活动且无卡片／边选区时 Delete 同样解散。

完整选中一个非空集合的所有成员再复制卡片时，集合也复制，生成新 ID 并重建成员映射；部分复制不带集合。内部连线沿用原有复制规则。保存、脱历史分享、PNG 导出、适应视图和只读回放均包含集合。

### 7-C. 批量整理

每次操作只作用于当前集合成员，作为一个可撤销步骤；共享成员在其他集合中的呈现同步改变。

- 水平中轴对齐：成员可见外框的 Y 中心对齐到整体包围框 Y 中心，X 不变。
- 垂直中轴对齐：X 中心对齐到整体包围框 X 中心，Y 不变。两种对齐都不保证消除重叠；需要消除重叠时使用网格排版。
- 网格排版：按原 Y、X、ID 稳定排序，以原左上边界为起点，列数为 ceil(√成员数)，使用最大实测宽高作为单元格、48 世界单位间距，横向居中、纵向顶对齐。不改变连线或内容。
- 统一核心宽度：默认 240 世界单位，可输入 90–800；公式、普通文字通过现有 0.5–6 倍缩放约束等比缩放，图片保持比例。因缩放上限和内容比例不同，最终核心宽度可能被限制，高度不强行相等。备注字号和阅读宽度保持原设置，卡片完整外框不保证相同大小。
